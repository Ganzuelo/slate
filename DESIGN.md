# Slate design requirements

These requirements apply to every app surface and all future UI changes. Read this file before changing the interface.

## Embedded Excalidraw exception

At the user's request, whiteboards retain Excalidraw's original interface, including its icons, toolbars, property panels, menus, dialogs, tooltips, and selection styling. Do not replace those controls with a custom Slate toolbar. Slate's surrounding shell continues to follow the requirements below. Keep whiteboard assets local, preserve keyboard focus, and route saving to Slate's vault.

## Icons

- Use **Lucide exclusively** for interface controls: navigation, toolbars, menus, dialogs, task metadata, and editor controls. User-assigned file, folder, bookmark, and document-tab symbols may use a bundled Unicode emoji choice instead.
- Use the shared `icon()` renderer and the bundled registry generated by `scripts/build-icons.mjs`. Add new icons there; do not draw replacement SVG paths by hand.
- Ship icons locally. No icon CDNs, remote fonts, or runtime downloads.
- Use a 24 × 24 viewBox, a 2px stroke, rounded caps and joins, no fill, and `currentColor`. Default display size is 18px; compact controls may use 14–16px. Keep the same stroke weight across sizes.
- Center icons consistently. Keep toolbar hit areas at least 28 × 28px even when the icon is smaller.
- Decorative SVGs are hidden from assistive technology. Every icon-only control needs an accessible name and a useful tooltip. Pair status icons with readable text.
- Emoji may appear as explicit user-assigned file/folder symbols and in the emoji picker. Render these with local system emoji fonts and preserve their natural colors; the Lucide color palette does not recolor emoji. Other interface controls remain Lucide. User-authored Markdown content, list punctuation, and task-format markers stored in files remain content and must be preserved.
- Native operating-system controls retain their platform appearance.

## Selection, hover, and focus

- Show selected tabs, navigation items, filters, and rows with a subtle neutral background and readable foreground color.
- The active document tab must flow into the page with no visible bottom border or seam. The tab strip divider may remain beneath inactive tabs and unused space; draw it behind the active tab surface.
- **Do not use ghost outlines, border-like selection shadows, purple bottom borders, or accent underlines to indicate selection.** Do not add these on hover or mouse click either.
- Keep hover quieter than selection and avoid layout shifts between states.
- Keep keyboard navigation visible: use a neutral, solid `:focus-visible` ring. Focus and selection are separate states; do not remove keyboard focus feedback to simplify the appearance.
- Inputs may show a neutral focus border. Canvas selection may use a neutral border and surface change to distinguish movable cards.
- Apply these rules in both light and dark themes, including dynamic content and dialogs. The selected app accent colors links and primary actions; it is not the selection-border color.

## Accent color

- Appearance settings provide named presets, a native color picker, hex entry, and reset to the default purple. Apply changes immediately and persist them with existing app settings.
- Use shared accent tokens instead of fixed purple values: `--accent-solid` for button/toggle/check backgrounds, `--accent-on` for their readable foreground, and `--accent` / `--link` for theme-adjusted decorative accents and links. Use the corresponding `--accent-check` asset for checkbox ticks.
- Keep navigation/row/card selection, keyboard focus, and text selection neutral. Preserve semantic error/destructive colors, syntax colors, user-assigned icon colors, and native emoji colors.

## Title bar and document tabs

- Use one continuous 40px title bar across the window. Group the left sidebar toggle and sidebar modes together, with document tabs starting at the editor's left edge.
- Place the right sidebar toggle next to the native window controls. Reserve the native controls' 138px at the outer window edge, never inside the editor column. Right sidebar content controls belong below the title bar.
- Keep document tabs compact, with softly rounded upper corners and concave lower shoulders on the active tab. The active surface merges into the page without a seam.
- Always show a note/view symbol in every tab, active or inactive. Explicit user assignments may use Lucide or emoji; the default note icon and New note menu items use `notebook-text`. Use `plus` for the New note button in the tab strip and `square-plus` for the New note button in the explorer toolbar. Keep inactive tabs quiet with a muted icon, title, and subtle separator; reveal their close button on hover or keyboard focus. The active tab shows its close button.
- Preserve native window controls, draggable empty title-bar space, clickable controls, and horizontally scrollable tabs. Collapsing a sidebar must not displace the window controls or hide the sidebar toggle.

## Context menus

- Use context-specific menus for files, folders, document tabs, editor selections, reading view, links, and explorer empty space. Right-clicking an inactive file or tab must not open it merely to show its menu.
- Capture the clicked path and file revision. Copy, move, rename, and trash act on that target, even when a different note is active. Preserve unsaved drafts and reject stale edits.
- Open menus at the pointer, clamp them to the window, and flip submenus when needed. Use compact rows, Lucide icons, neutral hover/focus surfaces, grouped separators, and red destructive actions.
- Support arrow keys, Home/End, Enter/Space, type-to-select, and Escape. Right/Left enter and leave submenus; clicking outside dismisses menus. Restore useful focus when closing.
- Tab closing must honor pinned tabs and pause for each unsaved draft. Cancel stops the remaining bulk-close operation.
- Editor menus preserve the selection while open, use the editor's undo history, and reject asynchronous paste into a changed note. Clipboard access is plain text; never interpret pasted HTML as app UI.
- Show only working actions. Independent editor panes, popout windows, note merging, and folder move/rename/delete require their own implementations before appearing in menus.

## UI controls

- Use shadcn/ui as the reference for dropdowns, selects, and related floating surfaces: compact triggers, 6px corners, 4px panel padding, subtle borders and shadows, and consistent 32px option rows.
- Keep shared styles in `public/controls.css` and select behavior in `public/controls.js`. Enhance selects with `SlateSelect.enhance(root, icon)`; preserve the original form values and change events. Native date and file pickers retain their platform appearance.
- Task metadata controls live in `public/task-controls.js` and are shared by the editor, reading view and task dialog. In the editor and reading view, set values show as quiet chips (due date, and urgency above Low) at the right edge of the task line, beside one Lucide "Task options" button; nothing sits in the typing path. A completed task is crossed out and quieted; its stored `✅` marker stays hidden, its completion date takes the date chip slot, and a green Lucide square-check takes the urgency slot. That button's menu offers the due date, the three urgency levels and Edit task. After a change, focus returns to the end of the task line so Enter starts the next task. Dialog date and urgency fields open the same calendar and urgency menu.
- Task date buttons open Slate's local, shadcn-style calendar directly. Keep one popup anchored to its trigger; clicking the trigger again closes it. Selecting or clearing a date applies immediately. Use Lucide month navigation, neutral selected days, visible keyboard focus, and matching light/dark surfaces.
- Task urgency offers three choices: Urgent (red Lucide square-exclamation-point), High (amber Lucide square-arrow-up), and Low (blue Lucide square-arrow-down). Keep text labels and tooltips so color is supplemental. Legacy medium displays as High; normal/unassigned and lowest display as Low. Preserve imported Markdown metadata and existing query semantics until explicitly edited.
- Use neutral hover, selected, and keyboard focus states in both themes. Select options show a Lucide checkmark; destructive menu items use theme-aware red.
- Tooltips match the active app theme: dark surfaces with light text in dark mode, light surfaces with dark text in light mode. Use shared surface, text, border, and shadow tokens, including the tooltip arrow. Adapt to system must respond to OS appearance changes while Slate is open; native title-bar controls follow the resolved theme.
- Floating lists must work inside modal dialogs, fit the viewport, dismiss on outside click or Escape, restore useful focus, and support arrows, Home/End, type-to-select, Enter/Space, and Tab.
- Use shared shadcn-style tooltips from `public/tooltips.js` and `public/controls.css` for all app hints. Set `data-tooltip` instead of native `title`. Center above/below the trigger horizontally or beside it vertically; ribbon hints open to the right. Tooltips must support keyboard focus, Escape, both themes, modal dialogs, and viewport collision handling. Use `data-tooltip-side` for an explicit preferred side.
- References: [shadcn Select](https://ui.shadcn.com/docs/components/select) and [Dropdown Menu](https://ui.shadcn.com/docs/components/dropdown-menu). Adapt these patterns to Slate's local JavaScript UI.

## Ribbon ordering

- Far-left toolbar buttons can be dragged vertically to reorder. Save the order in app settings and restore it across launches.
- Keep click actions separate from dragging. Escape cancels a drag. Show the dragged item with a neutral surface; preserve neutral keyboard focus.
- Provide Move up, Move down, and Reset icon order in each button's context menu, with Alt+ArrowUp/ArrowDown as keyboard shortcuts.

## Vault footer

- Place Settings immediately to the right of the vault-name button in the explorer footer.
- Clicking the vault name opens an upward dropdown listing known vaults, marking the current vault, and offering Manage vaults.
- Remember vaults across launches. The vault manager can open another folder, switch vaults, reveal the current folder, or remove an inactive vault from the list without deleting files.
- Preserve the workspace before switching and retain unsaved-change protection. A canceled or failed switch must keep the existing vault usable.

## Review before delivery

- Check both themes and selected, hovered, keyboard-focused, and disabled controls.
- Include sidebars, document tabs, settings, palettes, tasks, graph, canvas, and editor controls in the review.
- Confirm icons render from local assets, labels remain accessible, and long text does not crowd icons.
- Run `npm run build:icons` after changing the icon registry and `npm run build:editor` after changing the live editor. Commit generated bundles with their source and retained license notices.
